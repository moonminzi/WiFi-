NAGO VPN iOS 2.1.6

**2.1.6**
- **nagoing v2 — 진짜 TLS + 재전송 공격 방어** (관리자용, `--nagoing`)
  - TCP 443 폴백이 흉내가 아니라 **진짜 TLS 1.3** 핸드셰이크를 한다. 선 위에서는 평범한 HTTPS와 같고, 서버는
    nagoing이 아닌 접속에 일반 웹 서버처럼 404를 돌려준다
  - 연결(HELLO)을 기기의 WireGuard 키로 인증한다 — 남이 같은 연결을 가로채거나, 잡아 둔 패킷을 다시 보내
    끊거나 끼어들 수 없다(시각 창 + 재전송 창). 연결마다 새 암호 키를 쓴다
  - UDP 연결 시작도 QUIC 첫 패킷처럼 보인다
  - **서버도 v2로 올라가야 붙는다**(2.1.5 앱의 nagoing은 v2 서버에 안 붙음 — 이 버전으로 업데이트)

NAGO VPN iOS 2.1.5

**2.1.5**
- **막힌 망 우회(nagoing)** 추가 — settings → protocol → engine이 `nagotun`일 때 `--nagoing`을 켜면,
  WireGuard를 그대로 쓰되 443으로 감싸(UDP 51821 = QUIC 모양 → 막히면 TLS/TCP 443) 학교·회사·호텔처럼
  VPN을 막는 망에서도 붙는다. 패킷마다 난독화(무작위 nonce·패딩)하고, 지하철·엘리베이터 버스트 손실은
  FEC로 재전송 없이 되살린다. 망이 바뀌거나 서버가 재부팅돼도 빠르게 다시 붙는다(관리자용에서만 보임).
  - **서버에 nagoing 프록시(tcp 443 · udp 51821)가 떠 있어야 실제로 붙는다.** 설계·배포: `NAGOING.md`
  - 서버가 재시작된 뒤에도 손실 보정이 계속 되고, 끊을 때(stop) 오래 멈추지 않으며, 붙었던 UDP가 도중에 막히면
    한동안 TCP 443을 먼저 쓴다
- 최신 2.1.4(build 34, 지도 변경) 위에 다시 얹었다(build 35)
- (build 36) 트래픽이 적을 때도(통화·핸드셰이크) 손실 보정이 200ms 안에 동작한다. 끊을 때 앱이 멈칫하지 않고,
  settings에서 `--nagoing`을 끄면 저장된 VPN 프로필도 바로 일반 WireGuard로 돌아간다(자동 연결이 nagoing으로
  붙지 않음). 같은 기기의 다른 앱이 로컬 포트로 뭘 보내도 연결이 새지 않는다

NAGO VPN iOS 2.1.4

**2.1.4**
- 제대로 연결됐는데 `exit … KR ICN ! not JP — leak?`이 뜨던 것(잘못된 경고): 연결 전에 지금 회선 IP를 잴 때 열어 둔
  1.1.1.1 연결을 연결 뒤에도 다시 써서, 그 확인만 터널 밖(와이파이·LTE)으로 나갔다. 이제 잴 때마다 새 연결을 쓴다
  (net scan의 ipv6·doh·portal 검사도 같게). 막 붙은 직후 한 번 다르게 나오면 3초 뒤 한 번 더 보고 판단한다
- exit 줄을 길게 누르면 다시 잰다
- 서울에서 kr에 붙을 때 지도: 고리를 크게(22 → 34pt) 하고 지도 확대는 조금 줄였다. `you`와 `kr · seoul`을
  고리 아래 꼬리표 하나(`you ⇄ kr · seoul`)로 합치고, 연결되면 웨이포인트 번호(01·02·03)는 흐려지고 칸만 남는다
